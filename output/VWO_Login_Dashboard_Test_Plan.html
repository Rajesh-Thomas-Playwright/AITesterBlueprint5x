1. Objective

The goal of this test plan is to ensure the quality, functionality, security, accessibility and performance of the VWO (Visual Website Optimizer) login dashboard hosted at app.vwo.com.

The login dashboard is the entry point to VWO's experimentation, personalization and analytics tools. Testing verifies that it delivers a secure, intuitive and efficient login experience, as defined in the PRD, with the following success targets:

  • Login success rate of 95%+ successful authentication attempts
  • Login page load time under 2 seconds on standard connections
  • 90%+ user satisfaction for the login experience
  • Zero successful brute-force attacks or unauthorized access; no session hijacking
  • 100% compliance with security audit requirements
  • Login-related support tickets reduced by 20%

2. Scope

Scope of the test plan for the VWO Login Dashboard:

2.1 Functional Testing

  • Email and password login with secure validation
  • Remember Me (persistent login) checkbox
  • Session management with configurable timeout
  • Optional Multi-Factor Authentication (2FA)
  • Enterprise Single Sign-On (SAML, OAuth and other protocols) and optional social login (Google, Microsoft, other identity providers)
  • Forgot Password flow: email-based reset, secure token generation, password recovery options
  • Account registration link to the free trial signup
  • Product announcement banner (new UI launch, Light and Dark Mode)
  • Transition to the VWO core dashboard after successful authentication

2.2 Data Validation Testing

  • Real-time field validation on blur
  • Email format verification, including mobile keyboard type
  • Password strength indicator and enforced password complexity
  • Clear, actionable error messages for failed authentication

2.3 UI / UX Testing

  • Auto-focus on the first input field
  • Clickable form labels
  • Loading states during authentication
  • Brand consistency with the VWO design system
  • Light and Dark Mode theme support

2.4 Responsive and Compatibility Testing

  • Mobile-optimized, touch-friendly interface across supported browsers, operating systems and devices

2.5 Accessibility Testing

  • Screen reader support (ARIA labels), keyboard navigation, high contrast mode
  • WCAG 2.1 AA compliance

2.6 Security Testing

  • Encryption of authentication data in transit; HTTPS/TLS enforcement
  • Encrypted password storage using industry-standard hashing
  • Secure session token generation and management; session hijacking protection
  • Rate limiting against brute-force attacks
  • OWASP authentication guideline compliance

2.7 Compliance Testing

  • GDPR and CCPA data handling; enterprise security policies and audit trail support

2.8 Performance, Load and Scalability Testing

  • Page load within 2 seconds; compressed images; minified CSS/JavaScript; CDN usage
  • Thousands of simultaneous login attempts; behavior under traffic spikes (auto-scaling)
  • 99.9% availability; multi-region performance

2.9 Integration Testing

  • Hand-off to the VWO core platform and personalized dashboard
  • Login success/failure analytics tracking
  • Customer support system integration for login assistance
  • Marketing / onboarding / analytics tool integration

2.10 End-to-End User Journey Testing

  • New user: discovery, registration path, onboarding
  • Returning user: quick access, dashboard transition, recent activity context preservation
  • Error recovery: error identification, recovery options, success confirmation

2.11 Regression and Ad Hoc Testing

  • Regression after bug fixes or updates across the development phases
  • Exploratory testing to find hidden defects and usability issues

2.12 Out of Scope

The PRD lists the following under Future Enhancements; they are not tested in this plan: biometric authentication, adaptive (risk-based) authentication, Progressive Web App, and A/B testing, behavior analysis and personalization of the login page.

The scope may evolve during testing based on feedback, changing requirements or discoveries. It will be reviewed and adjusted throughout the testing phase.

5. Defect Reporting Procedure

  • Defect criteria: deviation from the PRD requirements, user experience issues, or technical errors.
  • Reporting steps: use the designated template with detailed reproduction steps, and attach screenshots or logs.
  • Triage: assign severity and priority, and assign to the appropriate team member for investigation and resolution.
  • Tracking tool: JIRA.
  • Roles: testers raise defects, developers fix them, the test lead triages and tracks.
  • Communication: defects found each day are sent to development management in an end-of-day status email.
  • Metrics: number of defects found, time taken to resolve, and percentage of defects successfully fixed.

6. Test Strategy

Step 1: Test design

  • Create test scenarios and test cases for the features in scope.
  • Test design techniques: Equivalence Class Partition, Boundary Value Analysis, Decision Table Testing, State Transition Testing, Use Case Testing.
  • Experience-based techniques: Error Guessing and Exploratory Testing.
  • Test cases are prioritized.

Step 2: Test execution procedure

  • Smoke testing first, to confirm the important functionality works.
  • If smoke testing fails, the build is rejected and we wait for a stable build.
  • On a stable build, perform in-depth testing using the test cases.
  • Multiple test resources test the application on multiple supported environments simultaneously.
  • Bugs are reported in JIRA and an end-of-day status email goes to development management.
  • Types of testing: Smoke and Sanity, Regression and Retesting, Usability, Functionality and UI, plus Security, Accessibility, Performance and Compatibility as described in Scope.
  • Test cycles repeat until the product meets the quality bar.

Step 3: Best practices

  • Context Driven Testing – testing as per the context of the application.
  • Shift Left Testing – start testing from the early stages of development rather than waiting for a stable build.
  • Exploratory Testing – in addition to normal test case execution.
  • End to End Flow Testing – multi-functionality scenarios simulating real user flows.
